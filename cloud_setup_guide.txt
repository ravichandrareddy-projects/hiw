A2. KEYS TO TAKE (2 values, copy exactly)
  1. Left sidebar gear icon -> "Project Settings" -> "API".
  2. Copy these two:
     KEY 1 — Project URL
         Looks like : https://abcdefghijklm.supabase.co
         Dart flag  : SUPABASE_URL
     KEY 2 — Publishable key  (older dashboards call it "anon public")
         Looks like : sb_publishable_...  OR  eyJhbGciOi...
         Dart flag  : SUPABASE_ANON_KEY
  3. RULES:

     - NEVER copy the "service_role / secret" key anywhere. The app

A3. SWITCHES TO FLIP (3 toggles, all in dashboard)
  1. Authentication -> Providers -> Email -> ENABLED (toggle ON).
  2. Authentication -> Providers -> Email -> "Confirm email" -> ON.
     (This makes sign-up send a 6-DIGIT CODE, which is exactly what
     the app's OTP screen expects. If OFF, sign-up sends a magic
     LINK instead and the app's OTP screen will never match.)
  3. Authentication -> Sign In / Sign Up -> "Minimum password length"
     is 6 by default. LEAVE it. (App cloud accounts need 6+ chars;
     the code tells the user this automatically.)

A4. SQL TO RUN (open: SQL Editor -> "New query" -> paste -> Run)
  The app uses Supabase AUTH for login (no SQL needed for that).
  BUT the app also mirrors meal logs + targets to the cloud, so
  run Q4 ONCE to create those two tables. Q1-Q3 are testing helpers.

  -- Q1. Confirm auth schema is healthy (expect: a count row)
  select count(*) as total_users from auth.users;

  -- Q2. List your test users (to see who registered)
  select id, email, confirmed_at, created_at
  from auth.users
  order by created_at desc;

  -- Q3. DELETE a test user so you can re-test register with the
  --     same email (register refuses duplicate emails, so you WILL
  --     need this while testing):
  delete from auth.users where email = 'youremail@gmail.com';

  -- Q4. REQUIRED ONCE: cloud tables the app syncs to.
  --     Safe to re-run (IF NOT EXISTS). Row-level security keeps
  --     every user locked to their own rows.
  create table if not exists public.meal_logs (
    id bigint generated always as identity primary key,
    user_id uuid not null references auth.users(id) on delete cascade,
    food_name text not null,
    calories int not null default 0,
    protein double precision default 0,
    carbs double precision default 0,
    fats double precision default 0,
    meal_type text default 'snack',
    logged_at timestamptz default now()
  );
  create table if not exists public.profiles (
    id uuid primary key references auth.users(id) on delete cascade,
    username text,
    target_calories int default 2000,
    streak int default 0,
    water_goal_ml int,
    updated_at timestamptz default now()
  );
  alter table public.meal_logs enable row level security;
  alter table public.profiles enable row level security;
  drop policy if exists "own meal logs" on public.meal_logs;
  create policy "own meal logs"
    on public.meal_logs for all
    using (auth.uid() = user_id)
    with check (auth.uid() = user_id);
  drop policy if exists "own profile" on public.profiles;
  create policy "own profile"
    on public.profiles for all
    using (auth.uid() = id)
    with check (auth.uid() = id);

A5. ADD KEYS TO THE APP + RUN
  # Run (dev):
  flutter run \
    --dart-define=GEMINI_API_KEY=AIza... \
    --dart-define=SUPABASE_URL=https://xyzcompany.supabase.co \
    --dart-define=SUPABASE_ANON_KEY=sb_publishable_...

  # Build (release test APK):
  flutter build apk --debug \
    --dart-define=SUPABASE_URL=https://xyzcompany.supabase.co \
    --dart-define=SUPABASE_ANON_KEY=sb_publishable_...

  Without the two SUPABASE flags the app silently stays on the
  demo mock account (user1@gmail.com / 1234). Nothing breaks.

A6. VERIFY SIGN-UP / SIGN-IN (do in this order)
  1. Fresh install, pass tester gate + onboarding until login.
  2. REGISTER with a REAL email, password 6+ chars -> app goes to
     OTP screen -> open inbox -> 6-digit code -> enter -> home.
     (Check Supabase Auth -> Users: your email appears, confirmed.)
  3. LOG OUT (Profile -> Logout) -> LOGIN with same email+password.
  4. Kill app, reopen -> still logged in (session persists).
  5. Wrong password -> clean "Wrong password" message, no crash.
  6. Re-register same email -> "Account exists. Try Login."

A7. SUPABASE TROUBLESHOOTING
  "Cloud login not configured"   -> flags misspelled or missing.
                                    Exact names: SUPABASE_URL,
                                    SUPABASE_ANON_KEY.
  No email arrives                 -> Confirm-email toggle OFF (see A3.2);
                                    check spam; free tier uses shared
                                    mailer (fine for testing).
  "Password should be 6 chars"   -> by design; use 6+ characters.
  "User already registered"      -> run Q3 above, then retry.
  OTP invalid/expired            -> codes expire; request a fresh one
                                    from the register screen.
